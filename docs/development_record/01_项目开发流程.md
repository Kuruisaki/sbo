# 1 项目开发流程

本章按时间和开发阶段整理了 27 个主要事件。阅读时抓住一个主线：先让单个翼型算得对，再让一批数据管得住，然后让模型能选点，最后才做自动优化和独立验收。文中用 A 表示“记录证明当时确实发生过”，B 表示“现在的代码确实这样实现”，C 表示“缺少记录，无法确认”。同一段可能同时涉及历史和当前实现，因此会标 A/B。历史命令为当时执行的核心调用，去掉终端包装后显示；完整原命令、包装器状态和输出在 [command_history.json](raw/command_history.json) 与 [execution_log.jsonl](raw/execution_log.jsonl)。这不是本次重新执行的记录。

## 1.1 项目最初目标

我们只改翼型的两个形状参数：弯度有多大，以及最大弯度靠前还是靠后。厚度保持为弦长的 12%，升力要求也保持不变。这样比较阻力，才能知道形状改动是否真的有用。

### 开发事件01：先形成方案，确认采用 XFOIL

先确定要解决什么问题和采用什么工具，当时只写方案，还没有开始生成计算代码。

**用户需求（A，2026-10-13）**来自线程“编写SBO流程与代码目录指南”（`01a133bb-c9f7-7ba2-ba1d-5db0b83e1224`）：

> 我希望跑通一遍”基于代理模型的优化（SBO）“的完整流程，请你：
>
> 1. 为我选择一个简单的航空外流算例，最好是行业比较常用、比较经典的。形成一份markdown格式的”部署指南“或者”流程指南“文档，包括几何来源、设计参数、目标函数、代理模型选择、操作流程等等各种描述性的信息，放在该项目的目录下；
> 2. 再为我形成一份markdown格式的”代码目录“文档，大致说明我需要撰写哪些代码文件、各代码文件的输入、输出、功能，依赖哪些python库，需要什么样的conda环境等等，注意不要生成具体代码，只是描述代码文件。该文档也放在该项目目录下；
> 3. 上述两份文件迭代修改，最终形成确实可行的一套方案。

Codex 提问是否必须使用体网格 CFD；保存的用户选择为“优先快速跑通，接受 XFOIL”。实际操作是查经典几何、XFOIL、GP资料，创建并交叉修订 `SBO_流程与部署指南.md`、`SBO_代码目录与接口设计.md` 至v1.1。最终回复明确“没有生成具体代码”，兼容性与气动效果须实施时实测。这一轮没有实际优化结果，不能把计划中的预算或改善写成已经发生。

根据当前代码实现（B），最终问题是连续 `x=[m,p]`、固定`t=0.12`、固定目标`CL=0.5`，在`Re=10^6,Mach=0.1,Ncrit=9,XTR=[1,1],TYPE=1`下最小化CD；基准`m=.02,p=.40`对应NACA2412。采用 GP（高斯过程）后，程序可以利用少量 XFOIL 结果预测其他参数的阻力，并同时给出预测的不确定性。只在代理模型上寻找最小值，找到的只是“模型认为不错”的位置；如果预测有误，真实阻力可能并不低。M4必须用真实XFOIL新点校正模型，M5必须用从未参与训练/选择的留出以及同精度独立复核判断泛化和收益。这个解释来自当前实现与方案，不是假造一段早期用户原话。

### 开发事件14：17个真实点拟合 GP，逐折独立LOO

用 17 个真实结果训练第一版模型，并逐个遮住答案检查预测误差。

**实现/文件（A）**：`surrogate.py`、`fitting.py`、`04_fit.py`、模型/LOO测试。

**实际执行（A）**：04先在`--stop-after-folds 3`边界停止，后续`--resume`完成；中间保存过一次 `Object of type bool_ is not JSON serializable`，随后修正布尔输出并续跑。

**输出（A）**：`iter_000`绑定原始17个train ID；LOO MAE=`9.818229810091269e-5`、RMSE=`.00014106218693489306`、最大误差=`.00037504887977025947`，MAE≤`.0002995`，不强制下一点探索。最终回复261项通过。

**当前实现（B）**：先按固定边界把输入换算到 0～1，再用 Constant×ARD Matérn(2.5) 核拟合 GP，并对输出做标准化（normalize_y）。矩阵稳定项 alpha 从 `1e-6` 开始，拟合有 5 次重启；只有 Cholesky 矩阵分解失败时才增大稳定项。每次留一验证都用剩余数据重新学习核参数、均值和标准差，不能借用被拿走点的信息。独立 holdout 的答案也没有进入这个阶段；这些术语的公式见第 04 章。
